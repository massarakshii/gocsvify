# accdbread: описание библиотеки

Oct 28, 2026 · @Александр

Пакет `accdbread` читает таблицы из файлов Microsoft Access (`.mdb` и `.accdb`) на чистом Go: только стандартная библиотека, без ODBC, mdbtools, cgo и сторонних модулей. Он разбирает бинарный формат файла сам и отдаёт список таблиц и содержимое любой таблицы в виде CSV.

## Назначение и общая суть

Библиотека решает две задачи: найти таблицы в базе и выгрузить выбранную таблицу в любой `io.Writer` (файл, буфер, сетевое соединение).

- **Поддерживаемые форматы:** Access 97 (Jet3), Access 2000/2003 (Jet4), Access 2007, 2010 и новее (ACE, `.accdb`).
- **Только чтение.** Файл открывается на чтение, база не изменяется.
- **Без побочных эффектов.** Функции верхнего уровня не печатают в stderr и не завершают программу: все проблемы возвращаются как `error`.
- **Два уровня API.** Простые функции `GetTables` и `ConvertToCsv` открывают файл на каждый вызов. Для нескольких операций над одной базой используйте `Open` и методы `*DB`: так файл читается и каталог разбирается один раз.

Простой пример:

```go
tables, err := accdbread.GetTables("base.accdb")
if err != nil { log.Fatal(err) }
for _, t := range tables {
    fmt.Println(t.Name, len(t.Cols), "колонок")
}

f, _ := os.Create("clients.csv")
defer f.Close()
err = accdbread.ConvertToCsv("base.accdb", "Клиенты", f, ',', 0)
if errors.Is(err, accdbread.ErrTableNotFound) { /* такой таблицы нет */ }
```

Не поддерживаются: файлы с паролем или шифрованием Access, индексы, связи между таблицами, запросы, формы и отчёты (читаются только таблицы с данными). Подробности и особенности есть в последнем разделе.

## Устройство файла Access

Файл Access — это массив страниц фиксированного размера, каждая из которых адресуется своим номером (смещение = номер × размер страницы). Библиотека никогда не загружает файл целиком: она читает нужные страницы по мере требования (`ReadAt`).

### Форматы

Версия формата хранится в заголовке по смещению `0x14`; библиотека смотрит на младший байт и выбирает один из двух наборов параметров.

| Версия Access | Младший байт версии | Набор параметров | Размер страницы, байт | Текст |
| --- | --- | --- | --- | --- |
| Access 97 (Jet3) | 0 | `jet3Fmt` | 2048 | однобайтовая кодировка |
| Access 2000/2003 (Jet4) | 1 | `jet4Fmt` | 4096 | UTF-16, часто «сжатый» |
| Access 2007, 2010+ (ACE) | 2 и выше (до 0x0F) | `jet4Fmt` | 4096 | UTF-16, часто «сжатый» |

Старшие байты слова версии у новых файлов (например `0x0103` у Access 2010) не несут разметки страниц, поэтому берётся только младший байт.

### Заголовок (страница 0)

- В начале файла — байты `00 01`, сигнатура `Standard Jet DB` или `Standard ACE DB` (смещение 4). По ней библиотека отличает файл Access от любого другого.
- Дальше от смещения `0x18` заголовок «замаскирован»: он прогнан через RC4 с постоянным ключом. Это не защита паролем, а такая же служебная обфускация формата, поэтому библиотека снимает её сама.
- Из расшифрованного заголовка берётся кодовая страница (смещение `0x3C`).

### Типы страниц

Первый байт страницы говорит, что на ней. Библиотеке нужны два типа:

- `0x01` — **страница данных**. В заголовке стоит номер страницы описания таблицы-владельца, затем число строк и таблица смещений строк.
- `0x02` — **описание таблицы** (TDEF): колонки, их типы и имена, ссылка на карту страниц данных. Если описание не помещается, оно продолжается на следующей странице и цепочка склеивается.

### Строки на странице данных

Строки уложены с конца страницы к началу, а их начала перечислены в таблице смещений в заголовке. Конец строки — это начало предыдущей. В каждом 16-битном смещении нижние 13 бит — адрес, а старшие — флаги:

- `0x8000` — строка удалена, библиотека её пропускает;
- `0x4000` — «указатель»: вместо самой строки лежит адрес другой строки (так бывает, когда после правки строка не поместилась на своё место).

Адрес строки во всём файле — это одно 32-битное число: **номер страницы × 256 + номер строки** на этой странице.

### Системный каталог

Список всех объектов базы лежит в служебной таблице `MSysObjects`. Её описание всегда на странице 2, так что чтение начинается с неё. Нужны четыре колонки:

| Колонка | Что хранит |
| --- | --- |
| `Id` | нижние 24 бита = номер страницы описания таблицы |
| `Name` | имя объекта |
| `Type` | `1` — обычная таблица (запросы, формы и т.д. имеют другие значения) |
| `Flags` | биты `0x80000002` помечают системные таблицы |

## Логика работы

Любой вызов проходит одну цепочку: открыть файл, прочитать каталог таблиц, найти нужную, собрать её страницы данных и разобрать строки. Шаги 1–3 нужны и для `GetTables`, шаги 4–7 — только для чтения данных.

`GetTables` выполняет шаги 1–3, `ConvertToCsv` — все шесть и затем пишет строки в CSV.

### 1. Открытие файла (`Open`)

Библиотека читает первые 256 байт и проверяет сигнатуру, определяет версию формата (из неё следуют размер страницы и смещения полей), снимает RC4-маскировку с заголовка, читает кодовую страницу и считает число страниц (размер файла ÷ размер страницы). Дальше все обращения к файлу идут через `page(n)`, которая проверяет, что номер не выходит за пределы файла.

### 2. Каталог таблиц (`Tables`)

Библиотека описывает таблицу `MSysObjects` (страница 2) как обычную и проходит по её строкам тем же кодом, что и по данным пользователя. Из каждой строки оставляются объекты типа `1` с непустым именем; системные отбрасываются, если `includeSys` не включён. Для каждой оставшейся берётся номер страницы описания (нижние 24 бита `Id`), дубли отбрасываются, описание загружается через `loadTable`, и весь список сортируется по имени без учёта регистра. Если описание одной таблицы не читается, в список всё равно попадает `Table` с заполненным `Err`: одна повреждённая таблица не ломает остальные.

### 3. Описание таблицы (`loadTable`)

Склеивает цепочку страниц TDEF и читает из неё: приблизительное число строк (`RowCount`), число колонок и число полей переменной длины, ссылку на карту страниц данных. Записи про индексы пропускаются: их длина известна, а содержимое не нужно. Дальше идут дескрипторы колонок (тип, номер, фиксированная или переменная длина, смещение, размер, точность и масштаб для `Numeric`) и следом имена колонок. В конце колонки сортируются по номеру, поэтому порядок в CSV совпадает с порядком в Access. Любая нестыковка смещений даёт ошибку «описание выходит за пределы» вместо паники.

### 4. Поиск страниц таблицы (`tablePages`)

Номера страниц данных берутся из «карты использования», на которую ссылается описание таблицы. Карта бывает двух видов: малая (стартовая страница и битовая маска прямо в строке) и большая (список ссылок на страницы с битовыми масками). Если карту прочитать не удалось, библиотека перебирает все страницы файла и берёт те, где тип «данные» и владелец — эта таблица. Это медленнее, но спасает при повреждении карты.

### 5. Чтение строк (`ForEachRow`)

Два прохода по страницам таблицы:

1. **Сбор целей.** Библиотека запоминает адреса, на которые ссылаются строки-указатели (флаг `0x4000`). Те строки лежат на своих страницах как обычные и без этой проверки попали бы в вывод дважды.
2. **Разбор.** Удалённые строки пропускаются; указатель разыменовывается в строку, на которую он указывает; строка, чей адрес был собран на первом проходе, сама по себе пропускается. Каждая строка передаётся в `decodeRow` и затем в ваш `fn`.

Если `fn` вернул ошибку, обход останавливается и эта ошибка возвращается вызывающему — так реализовано ограничение по числу строк в `ConvertToCsv`.

### 6. Разбор строки (`decodeRow`)

Строка состоит из четырёх частей по порядку: число колонок, поля фиксированной длины, поля переменной длины, а в конце — служебный блок (таблица смещений полей переменной длины, их число и маска NULL). Разбор идёт с конца, так как именно оттуда видно, где начинается каждое поле.

- **Маска NULL:** по одному биту на колонку. Необычно, но у `Boolean` значение хранится прямо в этой маске (бит установлен = `true`), отдельных данных у него нет.
- **Поля фиксированной длины** читаются по смещению и размеру из описания колонки.
- **Поля переменной длины** (текст, MEMO, OLE) — по таблице смещений: поле занимает диапазон от своего смещения до смещения следующего. В Jet3 таблица однобайтовая, поэтому для строк длиннее 255 байт добавлена дополнительная «таблица прыжков».
- **Таблицы без полей переменной длины:** таблицы смещений и счётчика в строке нет, после данных сразу идёт маска NULL.
- **Вычисляемые поля** (Access 2010+): значение обёрнуто в служебный заголовок из 20 байт, после которого идёт само значение.

Разбор одной строки защищён `recover`: повреждённая строка не роняет программу, а пропускается и увеличивает счётчик `badRows`.

### 7. Преобразование значений (`convert`) и CSV

Сырые байты поля превращаются в значение Go по типу колонки (таблица в разделе «Типы данных»). Длинные тексты и бинарные данные (MEMO, OLE) лежат отдельно, поле содержит только 12-байтный заголовок, а `readLval` по его флагам выбирает один из трёх способов:

- данные лежат прямо в этой же строке после заголовка;
- данные целиком в одной строке на другой странице, адрес которой стоит в заголовке;
- данные разбиты на куски: каждый кусок — это строка, начинающаяся с адреса следующего. Цепочка склеивается и обрезается до заявленной длины.

После этого `dumpCSV` пишет в `w` строку заголовка с именами колонок и по строке на каждую запись, переводя значения в текст функцией `fmtVal`. Экранирование кавычек и разделителей делает стандартный `encoding/csv`.

## Справочник API

Для быстрой задачи достаточно двух функций — `GetTables` и `ConvertToCsv`. Если нужно прочитать базу несколько раз или получить строки как данные, а не текст, используйте `Open`.

### Функции верхнего уровня

#### `GetTables(filePath string, cp ...int) ([]*Table, error)`

Возвращает пользовательские таблицы базы (без системных), отсортированные по имени без учёта регистра. Открывает файл, читает каталог и закрывает файл сама.

- `filePath` — путь к `.mdb` или `.accdb`.
- `cp` — необязательная кодовая страница текста для Access 97 (например `1251`). Используется только первый аргумент; без него кодовая страница берётся из заголовка файла.
- Возвращает ошибку, если файл не открылся, не является базой Access, имеет неизвестную версию или у неё не читается системный каталог (пароль, шифрование, повреждение).
- У таблицы, описание которой не прочиталось, заполнено `Err`. Проверяйте `t.Err != nil` перед работой с `t.Cols`.

#### `ConvertToCsv(filePath, tableName string, w io.Writer, delim rune, limit int, cp ...int) error`

Записывает одну таблицу в `w` в формате CSV: первая строка — имена колонок, далее данные.

- `tableName` — имя таблицы без учёта регистра. Системные таблицы этой функцией не находятся.
- `w` — любой `io.Writer`. Закрывать его должен вызывающий.
- `delim` — разделитель полей, например `','` или `';'`.
- `limit` — максимум строк данных; `0` означает «все».
- `cp` — как у `GetTables`.
- Если таблицы нет, возвращает ошибку, обёрнутую в `ErrTableNotFound` (проверяйте через `errors.Is`).
- Предупреждения о пропущенных строках здесь не возвращаются. Если они важны, используйте `Open` + `DumpCSV` + `Warnings`.

#### `ErrTableNotFound`

Ошибка-маркер: «таблица не найдена». В текст ошибки добавляется имя таблицы, поэтому сравнивать её нужно через `errors.Is`, а не `==`.

### Работа с одной базой несколько раз

#### `Open(path string, cpOverride int) (*DB, error)`

Открывает файл и возвращает дескриптор базы. `cpOverride = 0` означает «взять кодовую страницу из файла». После работы обязательно вызовите `Close`.

#### `(*DB) Close() error`

Закрывает файл. Обычно вызывается через `defer`.

#### `(*DB) Tables(includeSys bool) ([]*Table, error)`

Список таблиц. `includeSys = true` добавляет системные (`MSys…`) и прочие помеченные как системные таблицы; у них `System == true`.

#### `(*DB) ForEachRow(t *Table, fn func([]any) error) error`

Вызывает `fn` для каждой живой строки. Массив значений идёт в порядке `t.Cols`; `nil` означает NULL. Типы значений — в разделе «Типы данных». Если `fn` вернёт ошибку, обход прекратится и эта ошибка вернётся наружу. Не храните переданный срез без копирования, если расчитываете менять его позже.

#### `(*DB) DumpCSV(t *Table, w io.Writer, delim rune, limit int) error`

То же, что `ConvertToCsv`, но для уже найденной таблицы и уже открытой базы. Если у `t` заполнено `Err`, вернёт эту ошибку с именем таблицы.

#### `(*DB) Warnings() (badRows, badLval int)`

Сколько строк пропущено из-за повреждения (`badRows`) и сколько MEMO/OLE-значений не удалось прочитать (`badLval`; в этом случае в ячейке окажется NULL). Счётчики накапливаются за всё время работы с `DB`.

### Типы

#### `Table`

| Поле | Тип | Что значит |
| --- | --- | --- |
| `Name` | `string` | имя таблицы |
| `Cols` | `[]*Column` | колонки в порядке их номеров в Access |
| `RowCount` | `int` | число строк из заголовка таблицы; приблизительное, может отличаться от фактического |
| `NumVar` | `int` | число колонок переменной длины |
| `TdefPage` | `uint32` | номер страницы описания таблицы в файле |
| `System` | `bool` | системная таблица |
| `Err` | `error` | ошибка чтения описания; если не `nil`, `Cols` пусты |

Рассчитывать на `RowCount` как на точное число нельзя: в одном из тестовых файлов оно отличалось от реального на единицу. `Table` действителен только для того файла, из которого получен: в нём номера страниц этого файла.

#### `Column`

| Поле | Что значит |
| --- | --- |
| `Name` | имя колонки |
| `Type` | код типа Access (см. «Типы данных») |
| `Num` | номер колонки; тот же индекс бита в маске NULL |
| `Fixed` | поле фиксированной длины |
| `FixedOff`, `VarNum`, `Size` | где и сколько байт читать в строке (смещение для фиксированных, номер в таблице смещений для переменных) |
| `Calc` | вычисляемое поле Access 2010+ |
| `Prec`, `Scale` | точность и масштаб для типа `Numeric` |

### Параллельность

Отдельные вызовы `GetTables` и `ConvertToCsv` независимы и безопасны для параллельного запуска из разных горутин (проверено под `-race`). Один и тот же `*DB` из нескольких горутин одновременно использовать нельзя: счётчики предупреждений не защищены от гонок.

## Типы данных

В `ForEachRow` каждая ячейка — это значение типа `any`; в CSV то же значение превращается в текст функцией `fmtVal`. Деньги, даты, GUID и десятичные числа отдаются строками, чтобы не терять точность.

| Тип Access | Значение в Go | Пример в CSV |
| --- | --- | --- |
| Boolean | `bool` | `true` / `false` |
| Byte, Integer, Long, BigInt | `int64` | `-15` |
| Currency | `string`, всегда 4 знака после точки | `1000000.0000` |
| Single | `float32` | `444.555` |
| Double | `float64` | `0.1` |
| Numeric (Decimal) | `string` с учётом масштаба колонки | `-36.222200` |
| DateTime | `string` в формате `2006-01-02 15:04:05` | `1981-12-12 00:00:00` |
| DateTimeExt | `string` (текст из файла как есть) | — |
| Text, Memo | `string` | `Мир` |
| GUID | `string` в фигурных скобках | `{...}` |
| Binary, OLE | `[]byte` | `0x151c32…` (шестнадцатеричная строка) |
| Complex (вложения, многозначные поля) | `int64` — только связывающий номер, сами данные не читаются | `1` |
| Неизвестный тип | `[]byte` | `0x…` |

### Даты

Дата в Access — это число с плавающей точкой: целая часть — дни от 30 декабря 1899 года, дробная — доля суток. Время считается без часового пояса (UTC). Значения вне разумного диапазона (больше 3 000 000 дней по модулю), а также NaN и бесконечность дают NULL.

### NULL

NULL в `ForEachRow` — это `nil`, в CSV — пустая ячейка. Проблема: пустая строка и NULL в CSV неотличимы. Если это важно, читайте данные через `ForEachRow`. Особый случай — `Boolean`: NULL у него в формате не хранится (бит занят под само значение), поэтому вместо NULL всегда приходит `false`.

### Вычисляемые поля Access 2010+

Разбираются только типы Text, Long и Currency. Остальные выводятся как `0x…`: тип в описании такой колонки не всегда совпадает с типом результата, и лучше вернуть сырые байты, чем правдоподобное, но неверное число.

## Кодовые страницы, ограничения и особенности

Параметр `cp` влияет только на Access 97, и только для одной кодировки: русского текста в `windows-1251`.

### Кодовые страницы

- **Access 2000 и новее:** текст хранится в юникоде (UTF-16), `cp` игнорируется. Есть сжатый вариант (префикс `FF FE`, дальше однобайтовые символы, байт `00` переключает режим); библиотека распаковывает его сама. Смайлики и другие символы вне базовой плоскости читаются корректно.
- **Access 97:** текст однобайтовый. Если кодовая страница равна `1251`, байты переводятся как кириллица, иначе — как `windows-1252` (западноевропейская латиница). Кодовая страница берётся из заголовка файла или из параметра `cp`, если он передан и не равен нулю.

Практическое правило: сначала прочитайте базу без `cp`. Если вместо русских букв получились «Ïðèâåò», передайте `1251`. Другие однобайтовые кодировки (например `866` или `1250`) библиотека не знает: для них нужно дописать таблицу соответствия в `decode8`.

### Что не поддерживается

- **Файлы с паролем или шифрованием Access.** Системный каталог такого файла не читается, и `GetTables` вернёт ошибку.
- **Поля Complex** (вложения, многозначные поля, история версий MEMO): читается только связывающий номер, сами данные лежат в служебных таблицах и не подтягиваются.
- **Индексы, связи, запросы, формы, отчёты, макросы.** Читаются только таблицы с данными. Привязанные (ссылочные) таблицы у нестипа `1` не входят в список.
- **Вычисляемые поля** типов, отличных от Text, Long и Currency: только сырые байты.
- **Удалённые строки** не восстанавливаются: они пропускаются так же, как в самом Access.
- **Запись.** Библиотека только читает.

### Особенности поведения

- **Файл открывается на каждый вызов** `GetTables` и `ConvertToCsv`. Для нескольких таблиц из одной базы выгоднее один раз вызвать `Open`.
- **Повреждённые данные не роняют программу.** Плохую строку библиотека пропускает и считает, нечитаемый MEMO/OLE даёт NULL, плохую таблицу помечает полем `Err`. Всё это тихие потери данных, заметные только если смотреть `Warnings()`.
- **Регистр имён не учитывается.** Если в базе есть две таблицы, отличающиеся только регистром (в Access это невозможно), `ConvertToCsv` возьмёт первую из списка.
- **Память.** Строки читаются потоком и сразу пишутся в `w`, таблица целиком в память не загружается. В памяти держатся список страниц таблицы, адреса «перенесённых» строк и целиком одно значение MEMO/OLE.

### Что было проверено

- Разбор сверен на 85 тестовых базах из репозитория Jackcess (Access 97, 2000, 2003, 2007, 2010, 2019): 302 таблицы, число строк совпадает с заголовками таблиц, кроме одной, где счётчик в самом файле устарел.
- Проверены кириллица в формате Access 2003, сжатый юникод, смайлики, MEMO, OLE, числа с фиксированной точкой и даты до 1582 года.
- Обрезанные и случайно повреждённые файлы не вызывают паники и зависаний.
- 16 горутин, одновременно читающих один файл, под `-race` без замечаний.
- Не проверено на больших реальных базах и на файлах Access 97 с русским текстом в тестовом наборе; на вашем файле Access 97 конвертация по вашим словам прошла нормально.
